# Discover Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Discover section to the weekly digest: busy local threads from magazines the member doesn't follow, at most one per magazine. It appears in the email, the web digest and the Matrix notice.

**Architecture:** `digest` gets a pure `AddDiscover` step, run after `Build` and before `AddUnanswered`. It picks from the same `Hot` items. `mbin.Source.View` also returns the member's openable followed magazines, from the existing choices query. `run` wires the step in, stores the result in the digest JSON and records the picks as shown. `mail` and `bot` render the section.

**Tech Stack:** Go, pgx/Postgres (Mbin read-only), `html/template` and `text/template`.

**Spec:** `docs/superpowers/specs/2026-10-29-discover-design.md`

## Global Constraints

- `digest` reads nothing and writes nothing; all picking lives there.
- Every user-facing string is a placeholder until Task 6's wording review. Keep each string in one named constant or template spot so the review can change it in one place.
- No federated thread ever appears in Discover.
- A thread never appears twice in one digest.
- Fewer than 2 qualifying threads means no section in any channel.
- No migration: a stored digest without the new fields renders without the section.
- Before merge: `gofmt -l .` is empty, `go vet ./...` is clean, and `go test -race ./...` passes with `ENGAGEMENT_TEST_DATABASE_URL=postgres://postgres:test@localhost:55434/engagement_test?sslmode=disable`.
- CHANGELOG bullets go under `## [Unreleased]` and are at most 35 words; the changelog check enforces this.
- README and comments describe current state only, with no history and no rejected alternatives.

## Review Focus

1. A member who follows only hidden, deleted, adult or banned magazines must get the nudge, not names they can't open. Task 2 pins this.
2. A magazine title with a newline or HTML in it must not break the explainer line or inject markup. Tasks 2 and 4 pin this (`oneLine`, template escaping).
3. A digest stored before this change, read back by the web page or the Matrix notice, must render with no Discover section and no stray heading. Task 4 pins this.
4. A preview (`blankDigest`, empty `View`) must show Discover with the nudge wording and not panic on nil maps. Task 3 pins this.
5. A Discover thread must be recorded as shown, so next week neither Discover nor the main list repeats it without new comments. Task 3 pins this.

  - `TestDiscoverNeedsTwo`: with exactly 1 eligible thread, `d.Discover` is nil and `d.Following` is nil. With 2, both are picked.
  - `TestDiscoverFollowing`: `v.Following` holds 5 magazines. Assert `d.Following` is the first 3 and `d.FollowingMore == 2`. With `v.Following` nil and 2 eligible threads, `d.Discover` has 2 and `d.Following` is nil, which is the nudge case.
  - `TestUnansweredSkipsDiscover`: a key in `d.Discover` that is also in `fresh` is not picked by `AddUnanswered`.
  - `TestDiscoverEmptyView`: `AddDiscover(items, View{})` does not panic and picks from every magazine not in the main list.

Run: `go test ./internal/digest/ -run 'Discover|UnansweredSkipsDiscover'`
Expected: build failure, `AddDiscover` undefined.

- [ ] **Step 3: Implement.** Pull `Build`'s `sort.SliceStable` comparator out into `func sortRanked(rs []ranked)`, and make both `Build` and `AddDiscover` use it, so ties break the same way. `AddDiscover`:
  1. Collect the magazine IDs and keys of `d.Featured` and `d.More`.
  2. Keep each item that passes all of the exclusions in Step 1 (the same set `Build` applies, plus not-subscribed and not-federated, plus `v.Shown` excluded outright).
  3. Rank the kept items with `rank(it, v)` and sort them with `sortRanked`.
  4. Walk the sorted list, taking the first item per magazine until there are `maxDiscover`.
  5. If fewer than `minDiscover` were taken, leave everything unset. Otherwise set `Discover`, `Following` and `FollowingMore`.
